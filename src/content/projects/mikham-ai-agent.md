## زمینه و هدف

هدف این پروژه ساخت دستیار فارسی برای جمع‌آوری اطلاعات یک کسب‌وکار بود؛ کاربر باید بتواند طبیعی حرف بزند، اما خروجی نهایی باید با قرارداد دقیق سامانه مقصد سازگار باشد. مدل زبانی در اینجا تصمیم‌گیر نهایی نیست؛ نقش آن فهم پیام و پیشنهاد مقدار است.

## مسئله واقعی

گفت‌وگو مبهم و قابل اصلاح است، درحالی‌که API مقصد فیلدهای مشخص، شناسه شهر و دسته و داده معتبر می‌خواهد. اگر پاسخ احتمالی مدل مستقیماً ثبت شود، یک حدس می‌تواند به داده تولیدی تبدیل شود. همچنین پیام تکراری یا قطع شبکه نباید یک کسب‌وکار را دوبار ایجاد کند.

## معماری انتخاب‌شده

من جریان را به یک State Machine نسخه‌دار تبدیل کردم. هر نشست یک Draft ساخت‌یافته دارد و mutationها به نسخه مورد انتظار وابسته‌اند. فیلدها با Pydantic اعتبارسنجی می‌شوند و مقادیر وابسته به مقصد، مانند دسته یا شهر، از API معتبر resolve می‌شوند. پس از کامل‌شدن Draft، خلاصه قابل خواندن به کاربر نمایش داده می‌شود و فقط تأیید صریح اجازه ثبت می‌دهد.

فراخوانی نهایی با idempotency key انجام می‌شود. پاسخ HTTP به‌تنهایی موفقیت محسوب نمی‌شود؛ شناسه معتبر موجودیت ساخته‌شده نیز باید دریافت و بررسی شود.

## مدیریت خطا و امنیت

خطاهای ورودی، خطای مدل و خطای سرویس مقصد از هم تفکیک شده‌اند تا پیام قابل اقدام تولید شود. داده حساس وارد prompt غیرضروری نمی‌شود و لاگ‌ها باید پیش از ذخیره پاک‌سازی شوند. عملیات نشست به‌شکل اتمیک انجام می‌شود تا دو پیام هم‌زمان Draft را ناسازگار نکنند.

## آزمون و وضعیت

قراردادهای داده، انتقال وضعیت‌ها و مسیرهای تأیید/لغو قابل تست مستقل‌اند. تست مهم این است که بدون وضعیت confirmation هیچ فراخوانی ثبت انجام نشود. پروژه فعال است و گام‌های بعدی آن شامل ماندگاری قوی‌تر state، مشاهده‌پذیری و مجموعه ارزیابی برای مکالمات فارسی است.

## درس آموخته‌شده

قابلیت اطمینان یک Agent بیشتر از کیفیت یک prompt به مرز اختیارات آن وابسته است. وقتی مدل فقط پیشنهاد می‌دهد و کد قطعی اعتبارسنجی، state و اثر جانبی را کنترل می‌کند، رفتار سیستم قابل توضیح‌تر و قابل آزمون‌تر می‌شود.
