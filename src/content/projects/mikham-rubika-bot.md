## زمینه

ربات روبیکای میخوام راه دسترسی پیام‌رسانی به احراز هویت، آگهی‌ها، خدمات و دستیار ثبت کسب‌وکار است. چالش اصلی تعداد قابلیت‌ها نبود؛ جلوگیری از تداخل state چند جریان مکالمه بود.

## تصمیم معماری

Handlerها بر اساس دامنه جدا شدند و هر جریان داده موقت و transitionهای خودش را دارد. ارتباط با سامانه اصلی پشت یک سرویس API قرار گرفت تا جزئیات HTTP در handlerهای رابط پراکنده نشود. state پایدار موردنیاز با SQLAlchemy ذخیره می‌شود و داده موقت کوتاه‌عمر از موجودیت‌های اصلی جداست.

هر ورودی قبل از اثر جانبی با وضعیت فعلی سنجیده می‌شود. دکمه یا پیام قدیمی نمی‌تواند به‌سادگی مرحله جدید را دور بزند. خطای API نیز state را به موفقیت منتقل نمی‌کند و کاربر پیام قابل اقدام دریافت می‌کند.

## امنیت و آزمون

توکن‌ها خارج از مخزن نگهداری می‌شوند و لاگ پیام‌ها نباید اطلاعات احراز هویت را آشکار کند. منطق handler و سرویس API قابل تست جداگانه است؛ برای جریان کامل، سناریوهایی مانند لغو، بازگشت و تکرار پیام بررسی می‌شوند.

## نتیجه

پروژه فعال است و مرزبندی handlerها توسعه قابلیت تازه را کم‌ریسک‌تر می‌کند. درس اصلی این بود که state مکالمه باید بخشی از مدل دامنه باشد، نه چند متغیر پراکنده در callbackها.
